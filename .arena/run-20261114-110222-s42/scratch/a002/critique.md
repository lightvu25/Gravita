# Critique of `draft1.md` (Line-by-Line Engineering & Accuracy Audit)

Reviewing `draft1.md` against the verified codebase facts, architecture constraints, and 6-month maintainability goals reveals several concrete issues that must be resolved in the final rewrite:

## 1. Accuracy & Code-Verification Fixes
1. **Unverified Pause Symbol (`PauseMenuUI.IsPaused`):** Section 2 (Pillar 2) and Section 3 reference `PauseMenuUI.IsPaused` as if verified. While `PauseMenuUI.cs` was audited, `IsPaused` is not a verified static property in our Code Map. **Fix:** Base the `HitStopCoordinator` pause guard on verified `LevelFlowController` state (`LevelState.Playing` / `OnStateChanged`) and track an internal `isHitStopActive` boolean so an external `Time.timeScale == 0f` (e.g., pause menu) is never overwritten back to `1f`.
2. **Existing vs. Proposed Enum/Method Distinction:**
   - `HapticEvent.CrackedBreak`, `CloseCall`, and `LevelWin` do not yet exist in `HapticEvent.cs` (`0..6` only go up to `Death(6)`). **Fix:** Explicitly mark them as proposed additions to `HapticEvent` and `MostHapticsBackend`.
   - `CinemachineCameraZoom2D.SetVelocityOffset`, `PulseOrtho`, and `SetCutsceneOffset` are new APIs to add on top of the existing `normalOrthographicSize` / `targetOrthographicSize` / `zoomSpeed` fields. **Fix:** State clearly what currently exists vs. what is being added.
3. **Direct `PlayerSquashStretch` Unit Mismatch:** Pillar 2 table uses generic normalized scale values like `(1.12, 0.88)` and `(1.26, 0.72)`, whereas `PlayerSquashStretch` uses pixel-authored Inspector fields (`movingWidthPx: 20`, `movingHeightPx: 28`, `impactWidthPx: 28`, `impactHeightPx: 16`, `wallPressPx: 4`, `stretchAmount: 0.12`, `squashDuration: 0.22`, `stretchDuration: 0.18`, `maxDeformation: 0.3`). **Fix:** Express the tuning directly via `PlayerSquashStretch`'s real Inspector fields + tier amplitude scaling (and fix the exact North/East/West/South geometric behavior caused by `pivot (0.5, 0)` at `localPosition (0, -0.5, 0)`).

## 2. Technical & Runtime Bug Traps Found in `draft1.md`
4. **`CinemachinePixelPerfect` Zoom Override & Missing Fallback Option:** Diagnosis and Architecture flag `CinemachinePixelPerfect`, yet Pillar 1 relies heavily on smooth `OrthographicSize` breathing (`+0.20 u`, `+0.42 u`, `-0.16 u`) without providing a pixel-perfect-compatible alternative if `CinemachinePixelPerfect` must remain active. **Fix:** Add **Directional Camera Lookahead (`CinemachinePositionComposer` target bias along `CurrentDirection`)** as an immediate PixelPerfect-safe velocity framing companion/fallback alongside verifying `CinemachinePixelPerfect` vs. smooth ortho scaling in Play Mode.
5. **Double-Counted Redirect Chain Bug (`OnRedirected` vs. `MazeTile.OnAnyPlayerInteracted`):** Pillar 3 suggests subscribing to *both* `PlayerMovement.OnRedirected` and `MazeTile.OnAnyPlayerInteracted` (for `VectorPad`) to increment `currentChain`. If `VectorPad` also invokes `PlayerMovement.Redirect()`, this double-counts a single tile redirect. **Fix:** Specify a single canonical chain trigger or same-frame deduplication (`Time.frameCount` / `lastRedirectTile`) and keep tile recoil strictly scoped to `IPlayerInteractable.OnPlayerInteracted`.
6. **Wall vs. Brake/Gravity Stop Discrimination (`WasLastStopWallImpact`):** Pillar 2 didn't explicitly use `PlayerMovement.WasLastStopWallImpact` to prevent `OnMoveStopped` wall-impact handlers from firing on `BrakeTile` or `GravityBlock` captures. **Fix:** Route `OnMoveStopped` through `WasLastStopWallImpact` explicitly.
7. **Material Asset Mutation / Instantiation Leak on `HitFlashSprite.shader`:** Pillar 2 talks about changing `_FlashColor` (`#FFFFFF` vs. `#FF52C7`) on `Hit Flash White.mat`. Mutating `.material` creates runtime material instances; mutating `.sharedMaterial` dirties the `.mat` asset on disk. **Fix:** Recommend `MaterialPropertyBlock` (with `[PerRendererData]`) or swapping between two pre-authored read-only `Material` asset references (`sharedMaterial`) for `33–45 ms`.
8. **Duplicate Close-Call Camera Shake:** `CloseCallDetector` already has `cameraPulseForce: 0.06` serialized in `GameScene.unity`. Having `CloseCallFeedback` also trigger camera shake risks double-pulsing. **Fix:** Keep detection pure in `CloseCallDetector` (move shake trigger into `CloseCallFeedback` or zero `CloseCallDetector`'s direct impulse call once `CloseCallFeedback` owns it) so settings multipliers control every channel cleanly.
9. **1-Tile Micro-Shuffle Audio Fatigue:** At `moveSpeed = 30`, rapid 1-tile taps (`33 ms`) could make `tileCrossTick` chatter on every single hop. **Fix:** Start `tileCrossTick` softly at tile 1 (`vol 0.14`) and ramp upward from tile 2+, gated by `32 ms` minimum interval.

## 3. Scope, Clarity & Actionability Tightening
10. **Pillar 5 Scope Creep Risk:** Pillar 5 covers Coins, Stars, `VectorLauncher`, `Breaker`, `Freeze`, `Teleport`, `CircuitSwitch`, `EnergyGate`, and `LevelExit`—slightly crowded for one pillar, making numbers terse. **Fix:** Keep all mechanics tightly grouped under **Cohesive Lab Flow & Tactile Payoffs**, ensure every single sub-item has exact numeric parameters, and note `PowerUpController`'s `Shield`/`Echo` procedural fallback cleanup concisely (`lines 928–952` alongside `1448–1503`).
11. **Zero-Fluff Tightening:** Trim repetitive phrasing between Section 1 and Section 2 so each pillar reads like a crisp, ship-ready engineering spec with concrete code contracts and Inspector tables.
